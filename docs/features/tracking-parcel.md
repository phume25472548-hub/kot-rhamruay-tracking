# ติดตามพัสดุ

## ทำอะไร
ลูกค้ากรอกเลขพัสดุหนึ่งเลขหรือหลายเลขในหน้าแรก แล้วระบบดึงสถานะขนส่งจีน-ไทยจากช่องติดตามพัสดุในหน้าแรกของ CNS Cargo รวมถึงขนส่งต่อในไทย (เช่น Flash) มาแสดงเป็นไทม์ไลน์ใต้แบรนด์โคตรร่ำรวย คาร์โก้ ลูกค้าจึงไม่ต้องไปเปิดเว็บ CNS เอง

## ทำงานยังไง
1. ลูกค้ากรอกเลขใน `#track-number-input` (คั่นหลายเลขด้วย , หรือเว้นวรรค) แล้วกดค้นหาหรือ Enter ฝั่งเบราว์เซอร์เรียก `GET /api/track/<ข้อความที่กรอก>`
2. เซิร์ฟเวอร์นับคำขอต่อ IP ถ้าเกิน 20 ครั้งใน 1 นาทีจะตอบ 429
3. `splitTrackingNumbers` แยกเลขและตัดเลขซ้ำออก ถ้าไม่มีเลขหรือมีเกิน 10 เลขจะตอบ 400
4. แต่ละเลขส่งเข้า `lookupNumber` ทีละเลขตามลำดับ (ไม่ยิงไปที่ CNS พร้อมกัน)
   - ถ้ารูปแบบผิด (ต้องเป็น A-Z, 0-9, - ยาว 4–40 ตัว) จะได้ "รูปแบบเลขพัสดุไม่ถูกต้อง" โดยไม่ต่อออกไปข้างนอก
   - ถ้าขึ้นต้นด้วย `MOCK` จะได้ไทม์ไลน์ตัวอย่าง 5 ขั้น
   - นอกนั้นใช้ `fetchCnsTracking` ซึ่งเช็คแคชก่อน ถ้าไม่มีในแคชจึงดึง `https://cnscargo.com/home/index?waybillNo=<เลข>` (timeout 10 วินาที) ไม่ใช้ `/public/queryresult.html` เพราะหน้านั้นจบที่ "ถึงโกดังไทย" ไม่มีขั้นขนส่งในไทย
5. `parseCnsPage` อ่านจากโครงสร้าง HTML ใน `.TrackTrace`: ทุก `i.cur_circle` หรือ `i.circle` คือหนึ่งขั้น div ถัดไปตัวแรกคือวันที่ ตัวที่สองคือสถานะ แล้วเรียงตามวันที่จากใหม่ไปเก่า (ขั้นที่เวลาเท่ากันคงลำดับเดิมของ CNS) ข้อความสีแดงด้านบนเก็บเป็น `note` เช่น เลข Flash ถ้าข้อความนั้นคือ `ไม่พบรายการที่ค้นหา` และไม่มีขั้นเลย จะคืน `null`
6. แคชผลไว้ 15 นาทีถ้าเจอพัสดุ และ 5 นาทีถ้าไม่เจอ ถ้า CNS ล่มหรือ timeout จะไม่เก็บลงแคช
7. ฝั่งเบราว์เซอร์สร้างการ์ด 1 ใบต่อเลข จาก `#result-card-template` และ `#timeline-item-template` โดยใส่ข้อมูลด้วย `textContent` แสดง `note` เหนือไทม์ไลน์ และให้ขั้นแรกเป็น `active`

## ผลที่คาดหวัง
| เมื่อ | ต้องได้ | ตรวจด้วย |
|---|---|---|
| หน้า CNS ของ SF0210589618167 | 15 ขั้น ล่าสุดคือ "นำส่งสำเร็จ…" 05/11/2026 12:54 เก่าสุดคือ "ถึงโกดังจีน" 17/10/2026 17:30 และ `note` บอกเลข Flash TH01439B26WV4A | `parseCnsPage reads every step of a real CNS page, including the Thai carrier, newest first` |
| CNS สะกด "ผ่านพิธิศุลกากรไทยเรียบร้อย" | แสดงเป็น "ผ่านพิธีศุลกากรไทยเรียบร้อย" | เทสต์เดียวกัน |
| หน้า CNS ที่ไม่พบเลข | `parseCnsPage` คืน `null` การ์ดแสดง "ไม่พบรหัสพัสดุนี้ในระบบจัดส่งสินค้า" | `parseCnsPage returns null when CNS has no such number` |
| กรอก ` A1234, B5678  C9012,,A1234 ` | 3 เลข: A1234, B5678, C9012 | `splitTrackingNumbers splits on commas and spaces and drops duplicates` |
| กรอก `<script>` | "รูปแบบเลขพัสดุไม่ถูกต้อง" ไม่ต่อไปที่ CNS | `isValidTrackingNumber accepts letters, digits and dashes only` |
| ค้นเลขเดิมซ้ำภายใน 15 นาที | ไม่ยิงไปที่ CNS อีก | ไม่มีเทสต์ (ลองด้วยมือ: 0.40 วิ → 0.06 วิ) |
| IP เดียวค้นครั้งที่ 21 ภายใน 1 นาที | 429 "ค้นหาบ่อยเกินไป กรุณารอสักครู่แล้วลองใหม่" | ไม่มีเทสต์ (ลองด้วยมือแล้ว) |
| CNS ล่มหรือเกิน 10 วินาที | การ์ดของเลขนั้นแสดง "เกิดข้อผิดพลาดในการดึงข้อมูลจากเว็บขนส่งพันธมิตร" เลขอื่นยังแสดงปกติ | ไม่มีเทสต์ |

## กฎที่ห้ามพัง
- ข้อมูลจาก CNS ต้องใส่หน้าเว็บด้วย `textContent` เท่านั้น — กฎทางเทคนิค (กัน XSS)
- ยิงไปที่ CNS ทีละเลข และต้องผ่านแคชเสมอ — กฎทางเทคนิค (ไม่สร้างภาระให้เว็บต้นทาง)
- เลขพัสดุต้องผ่าน `isValidTrackingNumber` ก่อนส่งไปที่ CNS — กฎทางเทคนิค

## ไม่ทำและข้อจำกัด
- CNS ค้นได้ทีละเลข ถ้าส่ง `A,B` ไปในคำขอเดียวจะได้ "ไม่พบ" (ลองแล้วทั้งสองหน้า 2026-11-08) ระบบจึงแยกเลขเอง
- หน้าแรกของ CNS หนักราว 150 KB ต่อการค้นหนึ่งครั้ง (หน้าเดิมราว 11 KB) แคชจึงสำคัญ
- ยังไม่เคยเห็น `i.circle` (จุดเทา) ในหน้าจริง เพราะเลขตัวอย่างผ่านครบทุกขั้นแล้ว ระบบเก็บไว้ใน `done: false` แต่หน้าเว็บยังไม่ได้ใช้ค่านี้
- แคชและตัวนับคำขออยู่ในหน่วยความจำ จะหายเมื่อรีสตาร์ท และไม่แชร์กันถ้ารันหลายเครื่อง
- `req.ip` ยังไม่ได้ตั้ง `trust proxy` ถ้าวางไว้หลัง proxy ทุกคนจะถูกนับเป็น IP เดียวกัน
- ถ้า CNS เปลี่ยนโครงสร้าง HTML ระบบจะได้ไทม์ไลน์ว่าง และขึ้นว่า "พบพัสดุ แต่ยังไม่มีข้อมูลสถานะการขนส่ง"

## จะแก้อะไร ไปที่ไหน
| อยากแก้ | เริ่มที่ |
|---|---|
| วิธีอ่านหน้า CNS | `cns.js` → `parseCnsPage` |
| แก้คำสะกดของ CNS | `cns.js` → `STATUS_FIXES` |
| เวลาแคช จำนวนเลขสูงสุด รูปแบบเลข | `cns.js` → `FOUND_TTL_MS`, `NOT_FOUND_TTL_MS`, `MAX_NUMBERS_PER_SEARCH`, `TRACKING_NUMBER_PATTERN` |
| จำกัดจำนวนคำขอ | `server.js` → `isRateLimited`, `RATE_LIMIT_MAX` |
| ข้อความผลลัพธ์ของแต่ละเลข และข้อมูล MOCK | `server.js` → `lookupNumber`, `MOCK_TIMELINE` |
| การแสดงการ์ดและไทม์ไลน์ | `public/app.js` → `renderResultCard`, `renderTimelineItem` และ `<template>` ใน `public/index.html` |

## คำถามที่ยังเปิด
- เดิม API ส่ง `provider: "Global Cargo Network"` เพื่อซ่อนชื่อ CNS ตอนนี้เอาออกแล้วเพราะหน้าเว็บไม่ได้ใช้ ต้องซ่อนชื่อ CNS จากลูกค้าในส่วนอื่นด้วยไหม
- ต้องการให้หน้าเว็บแสดงขั้นที่ยังไม่ถึง (จุดเทา) ต่างออกไปหรือไม่ ต้องรอเลขพัสดุที่ยังเดินทางอยู่มาดูก่อน
